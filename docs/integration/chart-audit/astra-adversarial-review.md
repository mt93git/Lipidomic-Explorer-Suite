**Astra adversarial review of the Nexo chart audit reports**

Reviewed on 2026-11-08, branch `router/20261108-143544-a6f66a`, HEAD `8ad8063a262f1843fcf9910df34b5c912750e80c`. Scope: the thirteen requested reports, their committed evidence and audit scripts, cited commit diffs and test assertions, Nexo, the API, and the corresponding Team implementations. This is a repository review, not a new live audit. No R, API, browser, real/pilot data, dependency installation, or test suite was run. Only this report was written.

The claim that these reports establish complete parity does **not hold**. The strongest counterexamples are wrong/missing analysis downloads, a duplicate that returns an initialization placeholder, non-working cell-plot click instructions, and Size passes whose own evidence shows clipped labels. Many other passes establish a narrower behavior than the checklist requires. Conversely, the filtered-donut `ncols` diagnosis is correct, the cited commits exist, and the named regression tests contain meaningful assertions.

**Per-batch accounting**

A unit is one plot × one numbered check, evaluated against its latest explicit conclusion and any later correction. That gives 696 expected slots for 58 plots. The design report contributes twelve separately enumerated statements; the missing b04 log bundle and b05's contradictory closing signature/tally contribute one each: **710 units**. Fix SHAs, paths and assertions are supporting evidence, not additional units. A slot with no #12 conclusion is counted UNSUPPORTED and explicitly identified; this does not pretend the original plan contained #12.

CONFIRMED means the repository supports the *reported conclusion*, including an honest FAIL, OPEN, or not-reached result. It does **not** mean the product passed. UNSUPPORTED means the claimed breadth lacks appropriate evidence. CONTRADICTED means code, artifacts or another part of the report disagrees. A failed component makes the whole claimed check non-CONFIRMED; its working components are not counted again. P1 means a false pass/behavior claim obscures a visible defect in the reported run; P2 is an evidence gap; P3 is wording/bookkeeping. P1 does not assert that an unexecuted current build still reproduces every photographed defect.

HOLDS requires all reviewed claims to stand. HOLDS WITH GAPS means the remaining objections are evidence gaps or bookkeeping, with the report retaining its substantive open issues. DOES NOT HOLD means a P1 contradiction or an AGREE closure with an explicit open FAIL. Design's five plots overlap b01 and are not five additional catalog entries.

**Shared evidence defects**

**P — parity oracle.** A successful render with positive image dimensions proves a picture exists. Equal trace type/name/length proves structure, not equal x/y/z, values, labels, color scales or statistics. Most scripts do only those checks. In contrast, b02 round 2 compares PNG hashes or numeric coordinates (rounded to six significant digits), and b08 diffAllPlot adds same-size byte comparisons. Those stronger, scoped claims were retained. A missing standalone Team screenshot is not by itself a failure where a genuine payload comparison exists.

**D — control coverage.** The required quantifier is every applicable control, not “all controls counted, one changed.” The reports and scripts repeatedly conflate those. Shared-module schemas also include controls for other views, so enumerating their count is not a per-plot applicability map.
