# Adversarial review of the Nexo Phase 1B collaboration plan

**Verdict: buildable with these corrections. The plan is not an implementation-ready contract.** Its broad architecture can fit the stated boundaries, but its authorization, science ordering, recovery and checkpoint contracts do not. The advertised factory swap, small R changes and unchanged download path are contradicted by the code. Starting Phase 0 with those assumptions would validate a moving-card demonstration while leaving the expensive failures untouched.

Reviewed branch: `router/20261109-105516-84d9bc`; input HEAD: `d5b6bff744ffc7747f6d82074ec796b794db6263`. Application code was inspected at the requested base, `a95541a39bb0053bf8a74c116a3ac0a7fa5bed11`; the branch's changes above it are documentation/prototype artifacts. The current `nexo/phase1` ref has moved, so it was not substituted for that pinned base. Admin sources were read with `git show gh/stack-20261109:<path>` at `7b25aac7b8b21d97c97da3c140298a0d7abdac6c`, without checking out that branch.

**Counts: 10 P1, 13 P2, 1 P3.** P1 blocks building it as planned; P2 is wrong or missing but fixable; P3 is polish. Findings describe contradictions or missing contracts in the proposed implementation, not a claim that a nonexistent sidecar has already been exploited.

This is a static code review. No application code was changed, dependencies installed, tests run, services contacted or deployment attempted. ## Five corrections required before Phase 0 starts

1. **Replace the capability premise with an authorization contract.** Enumerate every collab and R route, workspace/project binding, protected document field and role action. Decide direct API versus gateway enforcement, non-reused session generations, Admin profile/name handling, expiry/revocation and the identity used for sidecar recovery/saves. The gate is two real identities plus raw HTTP/CRDT attempts: member A cannot read or mutate B, a Viewer cannot write, a client Editor cannot forge Finish/Confirm, and revocation takes effect on an existing connection. A link-visibility flag is not this gate.

2. **Specify one revisioned science commit and recovery protocol.** Draw the actual order of intent, authorization, R mutation, durable commit, publication and render. Include global settings, actions, statistics, Finish, save and restore, with idempotency and crash handling at each boundary. Define worker result identities and deduplication, project leases/admission and main/worker generations. Move collab/non-collab isolation into the first shared-session work. The gate is forced interleaving with real R: delayed PATCH replies, stale workers, timeout, save during edits and process restart must preserve the same committed science state in R and the document.

3. **Replace the factory-swap claim with a complete bridge/export specification.** Inventory direct store/tab writes and reconcile/bootstrap side effects; define local, remote, initialization and undo origins. Complete the Y.Doc schema, deterministic Team/Nexo projection, personal tab state, cross-reference constraints and count/byte admission rules. Prove Node SVG validation and command-history semantics using actual canvases. The gate includes 39 + two concurrent additions, snapshot/total byte boundaries, delete/move/restore races, actions/design/computed controls and flag-off regression behavior. Team's strict schema remains unchanged.

4. **Design versions as durable project records and scientific snapshots.** Specify version IDs, immutable blob references, actors, retention/GC, current-state download, fork and before-merge/before-restore semantics. Fix staff resolution of client-workspace checkpoints. Restore must coordinate R and document state, and its undo must preserve later authorized edits. Distinguish document durability from engine commitment and a Team-openable ZIP. The gate is staff/client save-download-reopen, viewer-only/last-editor departure, SQLite/ZIP crash recovery, cross-project retention, and a Team-opened version with matching scientific inputs and cohort—not merely valid JSON.

5. **Rewrite the spike, dependency graph and deployment checklist around those contracts.** Keep the mock two-card demo, but add the real authenticated HTTP/WebSocket path through nginx/tunnel, actual R race/recovery tests and a minimal backup/restore exercise. Pin the runtime/libraries and prove message rejection before relying on a named hook. Preserve the design prompt and unsent-edit protection when replacing autosave. Put expiry/isolation/security before client release, and follow/roles before their phone acceptance tests. Align prototype captions and PNGs with the selected contracts, then estimate the actual work. Do not carry the 31–41-day total forward as an established result.
